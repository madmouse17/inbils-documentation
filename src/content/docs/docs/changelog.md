What changed in Inbils, newest first. This page carries the latest entries of the project's [CHANGELOG.md](https://github.com/madmouse17/isp_inbils/blob/main/CHANGELOG.md); the full history is in the repository. The entries are written for engineers and ISP operators. Names such as "Buka kembali" are the Indonesian labels of the web app and the apps.

## Changed - Upgrade - Laravel 13 and PHP 8.5 (PHP2Shell) (2026-10-22)

- Owner request after PHP2Shell (CVE-2026-109618 and CVE-2026-109619): an unauthenticated remote code execution in the PHP interpreter, fixed in PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 (released 2026-10-21). It reaches FPM, mod_php, php-cgi and FrankenPHP, and only a PHP update closes it; Laravel is not the cause. The 8080 stack already ran 8.4.27 after a rebuild, Sail ran 8.4.26 and the host CLI 8.5.4. This change moves every runtime we control to PHP 8.5.12 and the framework to Laravel 13.38.
- **PHP.** `composer.json` requires `php ^8.4`: Symfony 8 needs 8.4.1, so the lock file no longer installs on 8.3, and there is no `config.platform` pin because Sail, the image and the host CLI all run 8.5. Sail builds `vendor/laravel/sail/runtimes/8.5` as the image `sail-8.5/app` (PHP 8.5.12 from the Ondrej PPA; `compose.sail.yaml`, for the app and for the opt-in `queue` and `scheduler` services). The deploy `Dockerfile` builds on `dunglas/frankenphp:php8.5-bookworm` (FrankenPHP 1.13.2, PHP 8.5.12 ZTS); its application stage stops the build below PHP 8.5.12, so a stale cached base cannot ship (build with `--pull`). PHP 8.5 deprecations removed: two `imagedestroy` calls in `CompanyLogoService` (a no-op since PHP 8.0), one `ReflectionMethod::setAccessible` call in a test, and the `PHP_VERSION_ID` switch around `PDO::MYSQL_ATTR_SSL_CA` in `config/database.php` (`Pdo\Mysql::ATTR_SSL_CA` exists from 8.4). Lint of all 1785 PHP files on 8.5.12 reports no compile-time deprecation.
- **Packages.** `laravel/framework` 12.70.0 to 13.38.0 and `laravel/tinker` 2.11.1 to 3.0.2. Pulled in by them: Symfony 7.4 to 8.1 (console, http-foundation, http-kernel, mailer, mime, process, routing, uid, var-dumper), `brick/math` 0.14.8 to 1.0.0 (no code of ours uses it; money is `bcmath` through `App\Support\Money`), `nesbot/carbon` 3.15.0, `guzzlehttp/uri-template` 2.0.1. Direct packages stay on their majors and move by minor or patch: `laravel/boost` 2.10.3 (with `laravel/mcp` 1.1.1, `laravel/roster` 1.0.0), `laravel/sail` 1.69.0, `laravel/pint` 1.32.1, `larastan/larastan` 3.13.0 (PHPStan 2.3.1), `laravel/sanctum` 4.3.3, `inertiajs/inertia-laravel` 2.0.28, `dedoc/scramble` 0.13.49, `spatie/laravel-medialibrary` 11.23.10, `tightenco/ziggy` 2.6.5, `phpunit/phpunit` 11.5.57, `brianium/paratest` 7.8.6, `mockery/mockery` 1.6.15, `nunomaduro/collision` 8.9.5. Not taken: Guzzle 8 (a new major that Laravel 13 allows), Inertia 3, PHPUnit 12 and 13, Spatie permission 8, activitylog 5, query-builder 7, nwidart modules 13. `composer audit`: no advisories.
- **Upgrade guide** (`laravel.com/docs/13.x/upgrade`). Handled: the CSRF middleware is `PreventRequestForgery` (`PlatformServiceProvider` and `config/sanctum.php` named the deprecated alias; the WhatsApp webhook test now pins that no webhook route carries the real class); the reset mail subject is the new key `Reset your password` (`lang/id.json`, same Indonesian text); Laravel 13 merges its own `monthly` log channel into every app, so `config/logging.php` defines it with the `RedactLogContext` tap that every writing channel needs; `serializable_classes` (next bullet). No change needed: the cache prefix, the Redis prefix and the session cookie name are set in app config files, so they stay as they were; session `serialization` is unset, which stays `php`, so nobody is signed out (Laravel 13's skeleton uses `json`: a separate decision); the one `upsert` names its `uniqueBy`; no `DELETE ... JOIN` with `ORDER BY` or `LIMIT`, no custom contract implementation, no `JobAttempted` or `QueueBusy` listener, no pagination view name, no global `array_first` helper.
- **Cache.** `config/cache.php` sets `serializable_classes` to `false` (Laravel 13's default; our file had no key, which keeps the old unrestricted unserialize): a cache store no longer returns any PHP object, it returns `__PHP_Incomplete_Class`. An audit of every `Cache::`, `cache` and rate limiter call found one entry that held objects, the customer home feed (`HomeFeedController`, 60 seconds): it cached two Eloquent collections. It now caches attribute rows and hydrates the models again on a hit, under the key `announcements:{company}:{version}:v2:customer:{id}`, so an entry of the old shape is never read and a rollback never reads the new one. The `array` store of the PHPUnit suite now serializes like Redis (`'serialize' => true`), so any object put into a cache fails a test; `tests/Feature/Support/CacheRefusesObjectsTest.php` pins both settings and `AnnouncementFeedTest` proves that a cache hit answers the same JSON without touching the feed tables. Nothing else changes in the API: `docs/api/mobile-v1.openapi.json` differs by one field, `openapi` `3.1.0` to `3.1.2` (Scramble 0.13.49), and old app builds keep working.
- **Tests.** Two tests needed a fix, neither a product bug. `ExceptionHandlingTest` found the `monthly` channel above. `WhatsAppPrivacyAndTenantTest` scans the stores for what the messages rendered; Laravel 13 adds the word `deleteWhenMissingModels` to every queue payload, so a Faker name that starts with the title "Miss" and is rendered into a message (the technician on the way) made it fail on some runs. The test world now uses fixed names for the admin, the customer and the technician.
- **Deploy.** No migration, no new `.env` key. Rebuild the four app images with `--pull`, recreate them, `queue:restart`, check `php -v` (PHP 8.5.12 or newer), `/up`, `/ready` and `/platform/login`. Do not run `cache:clear`: it would also drop the 24-hour mobile idempotency records, the throttle counters and the heartbeats of `/ready`, and nothing needs it. Steps, verification and rollback: `docs/operations/DEPLOYMENT.md`, "Laravel 13 and PHP 8.5 release". The E2E server and `docs:screenshots` run on the host's `php` (8.5.4-0ubuntu1.4 here): `sudo apt update && sudo apt install --only-upgrade 'php8.5-*'` installs `8.5.4-0ubuntu1.5`, Ubuntu's fix for CVE-2026-109618 (USN-8948-1).
- Docs: `PROJECT_GUIDE.md`, `README.md`, `docs/operations/{DEPLOYMENT,DOCKER}.md`, `docs/standards/coding-standards.md`, `docs/architecture/overview.md`.

The old `/webhooks/midtrans` stays for payments in flight and finds the company from the order; no removal date is set. `MIDTRANS_NOTIFICATION_URL` and `services.midtrans.notification_url` are removed.
- WhatsApp: one shared webhook `/webhooks/whatsapp`, routed by `phone_number_id` and signed with each company's own app secret; companies of one group may share a number. A customer's STOP or BERHENTI now withdraws consent only in the companies of the number that received it (it used to withdraw it in every company with a matching phone). The reconcile and sync commands report per company.
- E-mail: a company with its own SMTP row sends through it; without one it falls back to the platform sender (`MAIL_*`), which is never imported. RADIUS: the FreeRADIUS database is per company (`RadiusDirectory` builds `radius_{company id}` from the row), and the network pages say "RADIUS belum dikonfigurasi untuk perusahaan ini" with a link to the page when the card is off.
- Platform: a company's page in `/platform` lists every provider with state, Aktif and Terakhir diuji, never a value.
- Apps (`inbils-mobile`): Akun → Notifikasi uji in the customer and technician apps checks the notification permission, the registered token and a live test message with a 30-second countdown, with a Perbaiki hint per failing check. API `POST /api/v1/me/push-test` (202, 409 `push_token_not_registered`, 503 `push_unavailable`, 3 a minute) writes a `push_test` bell row and pushes to the requesting install only; the notification `type` enum gains `push_test`. The Integrasi page shows the platform Firebase state read-only (credentials set, last successful send).
- Deploy: `php artisan migrate --force`, then once per company `php artisan inbils:integrations:import-env --company=<code>` (`--provider=`, `--force`, `--dry-run`). Midtrans and WhatsApp are OFF for a company until it is imported or an admin fills its card, and RADIUS stays off. After the import the app ignores `MIDTRANS_*`, `WHATSAPP_*` and `RADIUS_*` except `WHATSAPP_GRAPH_VERSION` and `services.radius.coa_timeout`; `.env.example` and `config/services.php` mark them as import sources. `.env.e2e` needs `FIREBASE_CREDENTIALS` for the push E2E. Back up `APP_KEY` with the database: it now protects the integration secrets.
- Docs: `docs/user-guide/web.md` (section 8.9 Integrasi, the STOP rule, the platform card, RADIUS wording), `teknisi.md` and `pelanggan.md` (Notifikasi uji), `docs/operations/push-notifications.md`, `docs/operations/DEPLOYMENT.md`, `docs/business/{customer,billing,network}.md`, PDFs and `docs/api/mobile-v1.openapi.json` regenerated.
- Not built: a per-ISP Firebase project or white-label app, SMS, inheritance of integrations by a subsidiary, a "last webhook received" time for WhatsApp (a wrong app secret shows only as webhook 403 in the logs), Midtrans client key and merchant id (nothing reads them).

## Added - Panel perangkat: devices drawn like the physical unit, port register, rack, fibre path (2026-10-19)

- Lane `hardware-panel-ui`. Routers and NAS, switches, OLTs, ONTs, ODC/ODP and racks are drawn as an SVG front panel with the ports where the real ports are. A port shows only what Inbils knows: free or occupied, linked to another device, customer drop online or offline from the RADIUS session, isolir, admin down. There are no live link LEDs; SNMP and RouterOS polling stay out of scope.
- Pages: the panel card sits on `NetworkAssets/Show`, `NasDevices/Show` and `Odn/Asset`. `NetworkAssets/Trace` draws the fibre path from the OLT through the splitters to the customer's drop. A port opens a side sheet (`PortSheet`: bottom sheet on a phone) with the actions that already existed (assign or release a drop, trace, open the customer or subscription) plus label, admin state, note and "Hubungkan" to another device's port. A rack shows its U slots with the mounted devices.
- Schema (`Modules/NetworkAsset/database/migrations/2026_10_24_1100xx_*`, additive): `port_templates` (the company-independent catalogue, 14 models seeded from `Modules/NetworkAsset/database/data/port_templates.json`, new models need no deploy), `network_assets.template_key`, `port_layout`, `rack_asset_id`, `rack_unit`, `height_u` (the asset keeps its own layout copy, so editing a catalogue row never moves the ports of a device that uses it), and `asset_ports` (one row per physical non-ODN port, symmetric self link `linked_port_id`). PON ports and splitter outputs stay in `odn_ports`; the panel reads both and copies nothing.

- Docs: `docs/user-guide/web.md` section "Panel perangkat" with new screenshots (`docs/user-guide/images/web/panel-*.png`), `docs/business/network.md`, PDF regenerated.
